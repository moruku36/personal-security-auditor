# セキュリティ監査ツールの拡張ロードマップ

初期実装の進捗と、今後の拡張案を記載します。対応範囲を広げる前に、根拠の明確さ、予測可能な仕様、プライバシーを優先します。

## 初期実装の進捗

バージョン0.3.0ではFindingの安定ID・状態・証拠・制限とJSON schema 2、
Password Checkup／実効拡張権限の自己申告記録、ブラウザー別の検査範囲、
[対応・fixture・実機確認の表](coverage.md)、任意のローカルID／状態比較を追加しました。
詳しくは[手動確認と比較](review-and-comparison.ja.md)を参照してください。
以下は今後の追加・強化項目です。新機能の実機検証、adapterの型契約の拡充、
網羅的な状態fixture、他ブラウザーの実効権限取得、定期実行、修復機能の拡充は未完です。

## 現在の基盤

CLIは独立したscannerを`detect`、`scan`、`recommendations`で呼び出します。findingは不変で、レポート層にはrawコマンド出力やファイル本文を渡しません。OS検査はmacOSとWindowsの一部に対応し、Linuxは未対応範囲を明示します。ブラウザーごとの範囲は異なり、Chromeは上限付きmanifestと一部のWindowsポリシーを確認します。Brave／Edgeは現在拡張ディレクトリ数の集計、Firefoxはブラウザーの存在確認です。同等の監査として扱いません。詳細は[Windows検査範囲](windows.md)を参照してください。

## 優先順位

### 1. Scannerとfindingの契約を安定させる

- OS／ブラウザーadapterの型付き入出力と、版管理するレポートschemaを追加機能より先に定義する。
- findingに安定ID、カテゴリ、severity、状態、証拠の出所、制限を明示する。`unknown`／`unavailable`を`off`や否定判定と区別する。
- 可能な限りschemaを後方互換に拡張し、シリアライズ形式を変える前に互換性と移行方法を説明する。
- OS固有コマンドとCLI／レポート表示を結合せず、scannerを交換可能に保つ。

### 2. 証拠の種類とブラウザー対応差を分離する

- 保存パッケージのメタデータ、manifestの権限宣言、設定ポリシー、手動確認した実効設定、確認不能を別の証拠として表す。宣言だけから権限付与済み・有効化済みとは判定しない。
- まずChrome adapterを明確化する。認証情報ストアや他の個人プロファイル情報を読まずに実効状態を取得できない場合は、手動確認を案内する。
- Brave／Edgeは拡張ディレクトリ数、Firefoxは存在確認の範囲に留める。各ブラウザー固有のadapter、プライバシー審査、fixtureが揃うまで機能同等とみなさない。

### 3. Fixtureと実機検証マトリクスを作る

- 対応するOS／ブラウザーごとに、正常、無効、競合、不正形式、アクセス不能、不完全などを表す合成fixtureを追加する。
- CIでは合成データのみを使い、parser、上限、redaction、レポート互換性を検証する。CI runnerの成功は実機検証ではない。
- 実装状況、fixture、実機確認をOS・バージョン・ブラウザー別の表で管理する。記録は方法・範囲・限界に留め、端末結果、アカウント識別子、プロファイルパス、画像は非公開にする。
- 実機確認は実際の端末で実行した後にだけ記録する。1台や画面に見えた一つのブラウザー状態から一般化しない。

### 4. 収集データを最小限にする

- adapterごとに、読み取りを始める前に許可する項目とサイズ・件数上限を定める。raw出力より固定された状態値を使う。
- パスワード、Cookie、ブラウザー認証DB、Keychain／DPAPI秘密情報、秘密鍵本文、回復キー、秘密を含むファイル本文を読まない。拡張名・ID、サイト一覧、host pattern、プロファイルパス、アカウント識別子も、別途審査された機能で本当に必要でない限り収集しない。
- レポートはローカルでアクセス制限し、パスや識別子を伏せる。保護設定に失敗したら保存を中断する。Telemetry、アップロード、Remote APIは既定で追加しない。

### 5. ローカル比較と任意スケジュールを検討する

- ローカル比較は安定IDと状態の変化を要約し、schema変更や不完全スキャンを明示する。比較のためにraw出力や個人ブラウザーメタデータを保持しない。
- 定期実行を追加する場合はopt-inとし、実行が見えて停止・削除しやすく、必要最小限の権限で動作させる。実装前に頻度、保存先、保持期間、削除方法を文書化する。
- バックグラウンドサービスを黙って導入したり、監視を有効化したり、結果を端末外へ送ったりしない。

### 6. 修復は復元可能な安全策を整えてから広げる

- preview／dry-runを既定にする。適用前に変更を個別に表示し、変更ごとの明示承認を得る。
- 対象を狭い許可リストに限定する。変更前に保護されたバックアップを作り、検証済みrollback手順を用意する。復元できない場合も説明する。バックアップまたは事前条件の確認に失敗したら中断する。
- アクセス権の拡大、アカウント認証の変更、秘密のローテーション／失効、ブラウザー拡張の変更、OS／ネットワークのセキュリティ設定を無人で変更しない。安全かつ可逆な設計が示されるまでWindows ACL修復は対象外とする。

## 追加時のレビュー条件

新しいadapterや自動化には、データフロー確認、脅威モデル更新、合成回帰fixture、プラットフォーム別検証記録、unknown状態の説明を含めます。対応範囲の拡大を理由にプライバシーを弱めたり、確認用findingを根拠のない安全保証へ変えたりしません。
